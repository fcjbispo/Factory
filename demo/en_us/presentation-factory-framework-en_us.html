What is Factory?

Definition & Purpose

Factory is the software project management framework that integrates DDD and SDD, defining how projects are structured, documented, and evolved — by both humans and AI agents.

📋 What it manages

Documentation and project configuration. Source code lives separately at ~/Dev/Projects/.

🎯 Goal

Standardize the structure, documentation, and evolution of software projects.

👥 Target Audience

Humans and AI agents as first-class citizens.

🏛️ Paradigm

Integrated DDD (Domain-Driven Design) + SDD (Spec-Driven Development).

Workflow

🆕 New Project

PHASE 1
Initiation
→

Specification
→
PHASE 3
Development
→

Evolution

🔹 PHASE 1: Initiation

Scaffolding via MyCodebase, initial Bounded Context definition, Context Map creation.

🔹 PHASE 2: Specification

Spec creation for each Bounded Context, Ubiquitous Language validation, template configuration.

🔹 PHASE 3: Development

Spec-driven implementation, AI agents in action, continuous spec ↔ implementation validation.

🔹 PHASE 4: Evolution

ADRs for decisions, synced backlog (Factory ↔ MyBacklogManager), template-based documentation.

Workflow

🔄 Migrated Project (Legacy)

🔸 PHASE 1: Assessment

Existing code analysis, identification of implicit domains and subdomains, dependency and coupling mapping.

🔸 PHASE 2: Reverse Modeling

Bounded Context extraction from legacy code, Ubiquitous Language definition with stakeholders, Context Map creation (as-is vs. to-be).

🔸 PHASE 3: Contractualization

Retroactive spec creation per Bounded Context, gap identification (spec vs. actual implementation), documentation templates applied to legacy.

🔸 PHASE 4: Stabilization

ADRs documenting historical and new decisions, MyBacklogManager integration, AI agents configured, evolution plan to reduce technical debt per context.
